Org mode 非常强大，我过去也常常使用它。任务、大纲、笔记和时间记录都可以放在 Org 文件里，再通过自己的配置，把它们组织成一套顺手的工作系统。

**一句话结论**：如果你喜欢纯文本、愿意投入时间配置 Emacs，或者需要在 Linux、Windows 上工作，Org mode 免费、开放，灵活到几乎没有上限。如果你在 Mac 上，想要打开就能用的日历、任务和笔记，让 AI 把任务排进空闲时间，而不是自己维护一套配置，Void Calendar 更合适。

## 一览对比

| | Void Calendar | Org mode |
| --- | --- | --- |
| 平台 | macOS（Apple 芯片）；其他平台计划中 | Emacs 支持的系统；移动端有社区应用 |
| 价格 | 免费版含全部功能；Pro 同步未开售 | 免费开源 |
| AI 排程 | 自带模型，排进真正空闲的时段 | 无内置 AI 排程 |
| 日历连接 | Apple 日历与提醒事项、Google、iCloud | Agenda 视图；可单向导出 iCalendar |
| 任务与笔记 | 时间盒、任务、同名笔记、专注计时 | 纯文本大纲、TODO、时间记录、附件 |
| 数据存放 | 存在本机，公司不保存云端副本 | 你自己管理的纯文本文件 |

*竞品信息核对于 2026 年 10 月 8 日，以官网为准；Void Calendar 为公开测试版。*

但用久了以后，我发现自己也花了不少时间维护这套系统。尤其是想在电脑和手机之间接着做事的时候，文件同步、手机上的操作，以及图片和附件，都需要额外考虑。

## 有优秀的 Web 端，还是要把同步接起来

Org mode 有 [organice](https://github.com/200ok-ch/organice) 这样优秀的 Web 端，可以在手机和桌面浏览器里使用 Org 文件。

只是对我来说，能在浏览器里打开文件，还没有解决全部问题。文件放在哪里，怎样同步，换到另一台设备后能不能接着编辑，仍然需要自己安排。手机上临时记一件事、查看任务，再回到电脑继续做，也没有达到我想要的方便程度。

Void Calendar 目前是 Mac 应用，支持 Apple 芯片。Android 和 iOS 的专门客户端在计划中，Windows 和 Linux 也在计划中。我希望以后在不同设备上都能使用日历、任务和笔记，并得到适合各个平台的原生交互体验。

比如以后在学校用手机记下老师布置的作业，回到电脑再拆步骤、安排时间。我希望这些操作就是打开应用后接着做，而不是每次先想这份文件该怎样在设备之间流转。

## 贴一张图片，也不想先处理配置

做笔记的时候，你可能只是想把一张截图贴进去：老师讲过的图表、作业要求，或者自己查到的一段资料。

Org mode 支持图片链接和附件。但要把图片粘贴、保存位置和跨设备访问组织成自己习惯的方式，我当时还是需要写配置、选择工具，再把这些操作接起来。[Org mode 附件说明](https://orgmode.org/manual/Attachments.html)。

我当时确实写过一套复杂的配置。弄好的时候很有成就感，但换设备、改习惯，又要回来调整。后来我更想把时间用在事情本身：想到就记，打开就能做。

## 后来我还是选择了 OmniFocus

最后，我离开了那套花了很多时间配置的 Org mode 工作流，选择使用 OmniFocus。

Org mode 的强大并没有改变，只是我当时更需要一个打开就能开始管理任务的应用。对我来说，少一点配置和维护，能让我把注意力留给真正要做的事。

这也是我做 Void Calendar 时在意的地方：任务、笔记和日历放在一起，打开就能用。手机上随手记录、电脑上继续推进，是计划中的移动客户端要接上的那一步。

当然，OmniFocus 也有自己的痛点，我会在另一篇 [Void Calendar vs OmniFocus](/blog/void-calendar-vs-omnifocus) 里继续聊。

## 怎么选

选 Org mode，如果：

- 你已经在用 Emacs，或者愿意为一套自己的系统投入配置时间。
- 你需要在 Linux、Windows 和 Mac 之间使用同一套文件。
- 你希望数据就是纯文本，能用 Git 管理，不依赖任何一家公司。

选 Void Calendar，如果：

- 你主要在 Apple 芯片的 Mac 上工作，想打开就开始安排。
- 你需要直接连接 Google、iCloud 和 Apple 日历，而不是导出文件。
- 你希望 AI 用你自己的模型，把任务排进真正空闲的时间。
